# v0.1.0 — the catalog vertical slice, deployed

First tagged release of OpsAtlas: a service operations control plane that
catalogs services, records who owns them, probes whether they are healthy, and
scores them against production-readiness policy.

This tag is phases 0–10 of the slice-one roadmap, plus the deployment that
followed it. Everything below is built and tested. The things that are not built
are listed too, because a control plane that overstates itself is the failure
mode this project is trying to avoid.

**Running at <https://opsatlas.hoseacodes.com>.**

---

## What it does

**Declare a service, and the catalog maintains itself.** A team commits a
`service.yaml` to its own repository. OpsAtlas validates it against a versioned
JSON Schema, stores the normalized result, scores it against ten policy rules,
writes an audit event — all in one transaction — and then keeps probing the
health endpoints it declared.

### Catalog and ingestion

- `service.yaml` v1 JSON Schema, versioned, with six example manifests and eight
  invalid fixtures that each assert the exact JSON Pointer they fail at.
- Safe ingestion pipeline: size cap, safe YAML load, schema validation, violation
  mapping, then binding. A billion-laughs document, a `!!java` type tag, a
  duplicate key and a 70 KiB body are all refused before anything is constructed.
- Validation errors are structured and actionable — JSON Pointer, schema keyword,
  and a sentence explaining what to do about it.
- `POST`, `GET /{slug}`, `GET` with cursor pagination, `PUT` with `If-Match`.
  Re-registration is idempotent by manifest digest: a replay returns 200 and does
  not move `version`.
- Read-only GitHub source polling with conditional requests — an unchanged
  manifest costs a 304 and no ingestion. No webhooks, no write scope, ever.

### Governance

- Ten declaration rules, tier-conditional, with `NOT_APPLICABLE` as a first-class
  outcome and a moving denominator (a tier 3 service is scored out of 7, not 10).
- Audit log with correlation IDs, cursor-paged.
- `GET /api/v1/policy/rules` publishes the rule set and its rationale.
- The scorecard and the audit event are written inside the registration
  transaction — a forced mid-registration failure leaves no service, no scorecard
  and no audit row.

### Operations

- A Go observer probes every declared health endpoint with bounded concurrency,
  timeouts and jittered retries, and reports back.
- Observations are stored as rolled-up counters per environment per UTC day,
  never a row per probe, so storage is independent of probe frequency.
- A retention job prunes at 35 days, and the build fails if that window is
  narrowed below the 30-day ribbon the console draws.
- Ingestion is idempotent — a replayed batch applies nothing.

### Console

Next.js App Router: catalog, service detail, scorecard, register-by-paste,
sources. Status is carried by shape, height and weight — never by hue. Screenshot
any page, convert to greyscale, and every status is still readable. Colour is
rationed to four jobs: selection, focus ring, error-budget fill, open-incident
emphasis.

Real loading, empty, stale, partial-failure and error states. An environment that
has never been probed renders as an outline, not as a reading. Keyboard
navigation with a visible focus ring, asserted in a real browser.

### Authentication and authorization

- Every `/api/v1` endpoint requires a verified RS256 token. OpsAtlas is a
  resource server: it fetches public keys from the issuer's JWKS and holds no
  signing key, so it can check a token and cannot mint one.
- A verified token is not a membership. A caller whose issuer-and-subject pair
  has no row in `principal` gets **403, not 401** — they have a credential, it is
  simply not one this system knows.
- The first principal comes from configuration, not from the first caller.
  "Whoever authenticates first becomes the administrator" is a race with the
  internet, and losing it once is unrecoverable.
- The console holds no credential of its own. It forwards the signed-in person's
  token, so the audit log names the person rather than "the console".
- The observer carries a service credential, sent on its own header. Keys are
  stored as a SHA-256 hash; rotating one revokes the old one immediately.
- Prometheus scrapes with a credential of its own. The metrics endpoints are not
  open.

### Observability

- The correlation ID **is** the W3C trace ID when a request is traced. One string
  read off a failure searches the logs, the traces and the audit log.
- Trace context propagates observer → control plane: a probe, the report it
  produced and the state change that followed are one trace across two processes.
- Probes deliberately carry **no** trace context. A probe reaches a service
  OpsAtlas does not own, and injecting our identifiers into their logs is not our
  decision to make. A test fails if a probe ever sends `traceparent`.
- OTLP export is best-effort: a collector that is down costs a request nothing.
- Collector, Tempo, Prometheus and Grafana behind a compose profile.

### Contract and build

- OpenAPI generated from the code, committed, and drift-checked in CI.
- A typed TypeScript client generated from it. No hand-written API types.
- pnpm workspace plus Gradle, with `make` as the single entry point. No JDK needs
  to be installed — Gradle provisions a Java 21 toolchain itself.
- Container images for the control plane, console and observer, published to GHCR
  by tag.

## Deployment

One DigitalOcean droplet (2 vCPU, 4 GB, Ubuntu 24.04) running
`deploy/production/docker-compose.yml` behind Caddy, images pulled from GHCR by
tag, TLS from Let's Encrypt. Seven containers, one public hostname.

The production compose file is not the local one with different values, and the
difference is deliberate:

- Only Caddy publishes anything, and only 80 and 443. The local file publishes
  PostgreSQL and an unauthenticated MongoDB, which is correct on a laptop and an
  open database on a public IP.
- Every secret is `${VAR:?message}` with no default, so a missing one stops the
  stack naming itself rather than starting on a fallback committed to a public
  repository.
- Images are pulled by commit SHA or release tag and **never `latest`**. A
  running version you cannot name is one you cannot roll back.

Rationale and the runbook: [ADR 0014](docs/adr/0014-deployment-is-one-box.md) and
`deploy/production/README.md`.

## Verification

CI is green on this commit: six jobs on a clean runner — contract fixtures,
observer, console, OpenAPI drift, browser smoke, control plane.

Test counts as of this tag: 286 JVM tests, 35 Go tests (race-clean), 26 Playwright
tests against the whole real stack, console component tests, and 14 schema
fixtures.

Several guarantees are enforced by the build rather than by memory:

- `no_endpoint_escapes_this_test` enumerates every `/api/v1` mapping and fails the
  build unless each is covered by the cross-organization isolation suite or
  exempted with a written reason.
- `OrgIsolationIT` plants a second organization and a principal who belongs to
  it, then asserts that caller reaches their own catalog and not ours. Verified by
  mutation: hardcoding the organization in the resolver fails two tests.
- `PolicySetIT` parses the fleet table in the README and compares it to real
  scores, so a rule cannot quietly change its verdict.
- `ArchitectureTest` enforces module boundaries, and that only `integrations`
  makes outbound HTTP calls at all.
- `make check-secrets` runs first in CI and as part of `make test`.

## Known issues in this tag

Deploying this release found three faults that nothing local could have. All three
are fixed **after** this tag, so they are present in `v0.1.0` itself:

1. **The documented first start was impossible.** The compose file derived
   `OPSATLAS_BOOTSTRAP_ISSUER` unconditionally, and the control plane rightly
   refuses half an identity.
2. **The console image reports permanently unhealthy** while serving traffic
   perfectly. Its healthcheck uses `localhost`, which resolves to `::1` first,
   while Next binds IPv4 only. The control plane is unaffected — Tomcat listens
   dual-stack.
3. **`publish.yml` produced a `latest` tag** that it, and ADR 0014, both claimed
   it never did. The `latest` tags published for `0.1.0` should be treated as
   unusable; pull by the `0.1.0` tag.

If you are deploying this tag, take the fixes from `master` or add a healthcheck
override for the console service.

## What this release deliberately does not do

- **It is not multi-tenant.** The data model is single-tenant, shaped so that
  multi-tenancy is possible later. Every scoped table carries `org_id` and every
  query filters on it.
- **Health is probe availability, not an SLO.** It is the share of probes that
  succeeded from one vantage point against a health endpoint. A service can serve
  errors to every real user while its readiness endpoint answers happily.
- **The scorecard scores manifests, not running systems.** All ten rules are
  declaration checks.
- **There are no latency percentiles**, and there cannot be from what is stored:
  a sum, a min and a max are not a distribution ([ADR 0009](docs/adr/0009-observations-are-rolled-up-not-a-time-series.md)).
  Mean and max are reported, called mean and max.
- **No backups, no zero-downtime deploy, no redundancy.** `docker compose up -d`
  stops and starts containers. Do not assume the data survives the box.
- **Nothing has been load-tested or security-tested.** No performance, scale,
  availability or security claim is made anywhere, because none has been measured.
- **Logs are not shipped** to a log store. stdout JSON already carries the
  correlation ID, so Loki is deferred with a reason rather than left as a silent
  gap.
- **The observer detects no drift.** That needs a deployment concept that does not
  exist yet. A failed probe is an outage, not a drift.
- **Source polling does not scale on GitHub's unauthenticated rate limit** — 60
  requests an hour per IP is roughly five sources at a five-minute interval.
- **Catalog search and tier filtering happen in the console**, over one page only.
  The control plane has no search endpoint. This is not fleet-wide search.
- Incidents, cost attribution, dependency graph and blast radius are not planned
  for slice one.

There is **no mocked data anywhere in this repository.**

## Running it

```bash
make install       # install workspace dependencies
make up            # PostgreSQL, MongoDB and the Storm-Gate identity provider
make first-user    # create the local account and record its subject
make dev           # control plane on :8080
make dev-web       # in another terminal: the console on :3000
make dev-observer  # the prober
make up-telemetry  # optional: collector, Tempo, Prometheus, Grafana

make test          # everything that needs no running server
make test-all      # the above, plus the browser suite
```

Integration tests use Testcontainers and need a running Docker daemon.

## Architecture decisions

Fourteen ADRs, each with the alternatives it rejected. The ones that most shape
this release:

| ADR | Decision |
|---|---|
| [0001](docs/adr/0001-modular-monolith-as-one-gradle-module.md) | One Gradle module, boundaries enforced by an ArchUnit test |
| [0002](docs/adr/0002-safe-service-yaml-ingestion.md) | Parse to plain data, validate, *then* bind — never deserialize repository content into arbitrary types |
| [0005](docs/adr/0005-openapi-generated-committed-drift-checked.md) | OpenAPI generated from code, committed, drift-checked in CI |
| [0008](docs/adr/0008-polled-sources-not-webhooks.md) | Manifests are polled, never pushed, so OpsAtlas never holds write access to a monitored repository |
| [0009](docs/adr/0009-observations-are-rolled-up-not-a-time-series.md) | Observations are counters, never a row per probe |
| [0011](docs/adr/0011-correlation-id-is-the-trace-id.md) | The correlation ID *is* the trace ID |
| [0013](docs/adr/0013-authentication-via-storm-gate.md) | OpsAtlas verifies tokens and mints none |
| [0014](docs/adr/0014-deployment-is-one-box.md) | One box running compose behind Caddy, not an orchestrator |

Full list in [`docs/adr/`](docs/adr/). The phase list and target layout are in
[`docs/roadmap.md`](docs/roadmap.md).
